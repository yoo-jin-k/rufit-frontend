# FE-BUG01 · 낮은 창에서 종목 선택 복구

- 기준: PR40 `c7503cf4a19e32458cf27c4002f6e9d08eaa7971`.
- 브랜치: `developer`에서 `codex/exercise-picker-low-height` 생성 후 기준 커밋까지 fast-forward. PR은 developer 대비 누적이며 단독 변경은 기준 커밋 이후만 검토한다.
- 범위: ExercisePicker 레이아웃과 실패 시 오류 노출. 카탈로그, 미디어, 토큰, 운동 모델은 변경하지 않았다.

## 원인과 수정

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 320×300 첫 진입 | 시트 높이 251.156px, 목록 clientHeight 0. 실제 종목 클릭 시 헤더/필터의 포인터 가림으로 timeout | 제목·닫기만 고정, 검색·필터·결과·오류를 같은 FlatList 헤더로 스크롤 |
| 스크롤 구조 | 목록 밖 고정 요소가 높이 소진 | 세로 스크롤 하나. 필터의 기존 가로 스크롤 유지 |
| 입력 정체성 | 기존 state | 크기 분기/key 없이 React element 헤더, 실제 동일 DOM·초점·커서·필터 유지 |
| 오류 | 고정 영역에 표시 | 실패 시에만 오류 위치로 이동. 기존 alert 유지 |
| 닫기 | 48×48 및 onRequestClose | 유지, 목록을 내려도 실제 클릭 가능 |

기존 좌우 20px 여백은 목록 공통 패딩에서 항목·빈 상태·푸터의 margin으로 옮겨 이중 패딩을 피했다. 일반 타이핑/필터 갱신에 자동 초점이나 스크롤 초기화를 추가하지 않았다.

## 검증

| 경로 | 결과 |
|---|---|
| 처음부터 320×300 / 844×260 / 390×844 | 운동 시작 → 선택기 열기 → 검색 → 스쿼트 실제 선택 통과 |
| 선택 중 390×844 → 320×300 → 844×260 | 검색 `스쿼트`, 선택 범위 1–3, 동일 DOM/초점, 하체·바벨 필터 보존 |
| 목록 스크롤/닫기 | 실제 휠 스크롤 후 고정 닫기 실제 클릭. 844×260 목록 높이 103.75px |
| 원 운동 보존 | `0002`kg/`0020`회 완료 후 일시정지. 선택기 취소 후 전체 저장 원문 동일(휴식·일시정지 포함) |
| 결과 없음/직접 입력 | 빈 안내·직접 입력·취소 접근, `내 종목 01` 초안과 DOM 유지 |
| 출처 실패 | 테스트 브라우저 window.open 예외 주입, catch/alert/실패 시 스크롤 실제 검증. elementFromPoint로 오류가 가려지지 않음을 확인 |
| 재선택 | 벤치프레스 1회 추가, 원 세트 입력 유지 |
| 기존 검사 | styles:check·타입·lint·128 tests 통과, Web/Android/iOS export 통과 |

강제 클릭이나 세로 스크롤 중첩을 사용하지 않았다. DOM 테스트에서 칩의 기존 RNW aria-selected 전달이 없어, 실제 필터 결과 요약과 도구 버튼 표시로 상태를 확인했다. 해당 접근성 동작은 이 수정에서 변경하지 않았다.

## 재현 자료

`verification/exercise-picker/`:
- `before.json`, `before-320.png`: 수정 전 0px 목록 실측과 실패 로그/PNG.
- `capture-before.cjs.txt`: 최초 계측 스크립트(이 작업 환경 경로 포함).
- `reproduce.cjs`: 실제 클릭 회귀 검사. 동일 검사로 기존 빌드에서 실패(`regression-before.txt`), 수정 빌드에서 통과(`results.json`).
- `after-initial-*.png`, `search-*.png`: 해당 이름의 초기 창 너비, 높이는 위 표. 모달 안정화 후 캡처.
- `list-from-*-to-844.png`: 각각의 초기 너비에서 844×260으로 회전한 뒤 목록 스크롤.
- `error-*.png`: 각 시나리오 마지막 320×300에서 링크 실패 오류 노출.

```sh
PLAYWRIGHT_PATH=/absolute/path/to/playwright \
PICKER_URL=http://127.0.0.1:8098 \
node docs/verification/exercise-picker/reproduce.cjs
```

실제 Chrome이 필요하며 새 격리 브라우저 저장소만 사용한다. `PICKER_OUTPUT`으로 결과 폴더를 지정할 수 있다. 수정 전 빌드 URL을 넣으면 첫 스쿼트 선택에서 실패해야 한다.

네이티브 키보드/OS 글자 확대/실기기 스크린리더는 검증하지 않았다. 웹 가용 높이 감소를 네이티브 키보드 검증으로 해석하지 않는다.
