# iOS 실기기 제보 수정 및 재검수

사용자 제공 재연 체크리스트를 기준으로 수정했습니다. 아래 ‘코드 적용’은 실기기 재현 해소 확인과 다릅니다.

| 항목 | 코드 적용 | 남은 검증 |
|---|---|---|
| 1-1, 1-4 로그인 후 터치 불가 | iOS 인증 UI를 앱 내부 레이어로 표시하여 시스템 인증 브라우저와 네이티브 시트 중첩을 제거합니다. 로그인 성공 시 닫고 이미 종료한 브라우저의 중복 dismiss를 방지합니다. | 카카오·구글 로그인 직후 탭/스크롤/다시 계정 열기를 실제 아이폰에서 확인해야 합니다. |
| 8-1 상단 버튼 잘림 | 모든 공통 모달에서 SafeAreaProvider를 독립적으로 생성하여 모달 화면 기준 안전 영역을 측정합니다. | 오늘 기록·운동 상세·삼대측정 최초 진입과 반복 진입, 닫기를 확인해야 합니다. |
| 5-11 권한 거절 뒤 작성 차단 | 사진 선택 실패 안내는 유지하되 기존 글·사진 저장은 허용합니다. 촬영 권한 요청은 촬영 동작에만 한정합니다. | OS 설정에서 카메라를 끈 뒤 촬영 거절, 글 저장, 앨범 선택을 확인해야 합니다. |
| 2-7 세트 드래그 | 핸들을 잡는 순간 부모 스크롤을 잠그고 놓기·취소 시 해제합니다. | 실제 손가락 드래그와 드래그 후 일반 스크롤 복구 확인이 필요합니다. |
| 2-1 시간 | 운동 시간을 분:초로 표시합니다. | 일시정지·재개·잠금 후 실제 시간 확인이 필요합니다. |
| 2-1 빈 운동 종료 | 완료 세트가 없으면 확인창을 거쳐 기록 없이 종료합니다. 기존 이력은 보존하고 운동일 수는 증가시키지 않습니다. | 취소와 확인을 각각 확인해야 합니다. |
| 8-6 연결 복구 | 게시물·서버 운동 기록·운동 중 친구 목록의 네트워크 오류에 한해 5초 간격과 앱 복귀 시 읽기를 재시도합니다. 성공 응답 후 오류를 지웁니다. 저장·삭제 자동 재전송은 하지 않습니다. | 사용자가 오류를 본 정확한 화면에서 재확인해야 합니다. 이 외 화면의 복구는 별도 점검 대상입니다. |
| 8-7 계정 선택 | 네이티브 Google 인증 요청에 prompt=select_account를 추가합니다. | 두 실제 계정으로 서버 자료 분리를 검수해야 합니다. 기기 기록은 기존 정책상 공유되는 로컬 기록이며 계정 서버 기록과 구분됩니다. |

## 검증
- 스타일 생성 일치, TypeScript, ESLint, 자동 테스트 264개 통과(실패·건너뜀 0).
- iOS JavaScript/Hermes 배포용 번들 생성 성공. 실기기 실행 성공을 뜻하지 않습니다.
- 브라우저 생명주기, 실패한 사진 첨부 후 기존 글 저장, 조회 재시도 중복 방지/정리, 빈 운동 종료 후 이전 이력 보존을 자동 검증합니다.
- 기존 package.json의 사용자 prebuild 변경은 본 수정 커밋에서 제외합니다.
- 실제 계정의 운동/사진/친구 데이터는 변경하지 않았습니다.
