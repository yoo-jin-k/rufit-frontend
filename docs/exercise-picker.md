# 그림으로 고르는 종목과 세트 편집

운동 시작 → 종목 추가 → 이름 검색/부위/도구 필터 → 사진이 있는 종목 선택 → 무게·횟수 입력 흐름이다. 스쿼트 검색에는 바벨, 맨몸, 덤벨, 프론트 스쿼트가 나온다. 이름 공백과 영문 대소문자를 무시하며 일부 별칭(사레레, 턱걸이 등)을 지원한다. 필터는 함께 적용하고 검색 초기화로 해제한다. 검색 결과가 없으면 이름을 직접 입력할 수 있다.

- `＋`: 해당 행의 무게·횟수를 그대로 복사하고 바로 다음 행에 추가한다. 새 ID이며 완료 여부는 false다.
- `−`: 해당 행만 삭제한다. 남은 행의 번호를 다시 표시한다.
- 마지막 세트를 지우면 종목은 남고 새 빈 세트를 추가할 수 있다.
- 체크: 올바른 입력만 완료할 수 있다. 완료된 세트를 잘못된 값으로 편집하면 완료가 해제된다.
- 한 운동의 전체 세트는 최대 300개다. 종료한 기록은 수정·복제·삭제를 막는다.
- 사진이 있는 종목은 같은 운동에서 중복 선택하지 않는다. 같은 종목의 추가 기록은 세트 복제를 사용한다.
- 연속 입력은 최신 저장 상태에서 적용하며 저장 요청은 순서대로 처리한다. 세트 ID·catalogId·미완료 입력도 재실행 시 복구한다.

현재 화면은 로컬 기록 모드다. 18개 종목과 사진은 앱에 포함되며 네트워크가 없어도 쓸 수 있다. 기존 사용자 직접 입력 기록에는 catalogId가 없으므로 사진을 임의로 연결하지 않는다. schemaVersion 1 형식과 이전 이력을 보존한다.

catalogId는 백엔드 공용 종목 UUID와 일치한다. 최초 10개는 V10, 추가 8개는 V20 마이그레이션에서 제공한다. 서버 ID와 화면의 종목 인스턴스 ID는 서로 다르다. 실제 서버 저장 연결은 아직 없으며, 나중에 연결할 때 이 catalogId를 API의 exerciseId로 전달해야 한다. 이 PR의 직접 입력 종목은 로컬 항목이며 서버 공용 목록을 수정하지 않는다.

사진 이용 조건과 원본은 [자산 출처](../assets/exercises/README.md)에 기록했다. 목록의 이미지를 교체할 때 UI와 운동 기록 로직을 변경할 필요가 없도록 catalog.ts / images.ts / ExercisePicker.tsx를 나눴다.

## 검증 (2026-09-13)

- 프론트 36개 자동 테스트, 앱·도구 타입 검사, 린트 통과.
- Android/iOS/Web 정적 번들 생성 통과. 실기기 설치 검증은 아니다.
- 브라우저의 별도 테스트 주소에서 375×812와 320×690 너비 확인, 가로 잘림 없음.
- 검색 4건 → 하체+덤벨 1건 → 가슴+덤벨 0건 → 초기화 확인.
- 스쿼트 1kg 2회 완료 → ＋ 연속 두 번으로 독립된 미완료 2세트 추가 확인.
- 복제한 행만 3kg으로 변경 → 다른 행 삭제 → 새로고침 후 1kg/3kg·횟수·완료·사진 연결 유지 확인.
- 마지막 세트 삭제/빈 세트 다시 추가, 이미 선택한 종목 비활성화, 직접 입력 확인.
- 미완료 제외 확인 후 종료 → 새로고침 후 완료 이력과 버튼 비활성화 확인. 브라우저 오류 로그 없음.
- 사용자 기존 8081 화면과 저장소를 건드리지 않고 8092에서 테스트 데이터를 사용했다.
