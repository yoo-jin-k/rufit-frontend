## 현 상태와 유지할 보장

- useWorkoutArchive는 ready/failed/status와 latest.current/generation을 관리한다. 문구를 상태 판별에 사용하지 않도록 대체한다.
- createWorkoutStorage는 저장본을 호출 시 직렬화하고 순차 저장한다. 느린 이전 쓰기가 다음 쓰기를 덮지 않으며 실패 후 다음 저장도 진행된다.
- ready 전 운동 변경은 차단한다. 손상된 읽기 결과를 빈 아카이브로 저장하지 않는다.
- 재저장은 latest.current 전체를 저장한다. pause/complete/adjust 명령을 다시 실행하지 않는다.
- 완료 이력은 history에 있고 다음 운동 준비 시에도 메모리에 유지된다. 저장 실패 중 앱 종료 시 최신 메모리의 영속성까지 보장하지 않는다.

## 제안 상태

| 상태/필드 | 의미/불변 조건 |
| --- | --- |
| state | loading / load-error / saving / saved / save-error |
| ready | 편집 가능한 아카이브를 성공적으로 읽었는지. load-error/loading 최초 단계에서는 false |
| retryPending | 사용자 재시도 작업의 처리 중 여부. 렌더 직전 연속 탭도 동기적으로 잠금 |
| unsavedAfterFailure | 마지막 최신 쓰기 실패 이후 아직 최신 쓰기 성공을 확인하지 못했는지. 새 편집/재시도 시작만으로 해제 금지 |
| generation | 쓰기마다 증가. 완료 콜백이 현재 generation과 일치할 때만 saved/save-error와 실패 기억 변경 |
| loadRequest/epoch | 읽기 실행과 생명주기 식별. 이미 완료/교체/해제된 작업의 늦은 응답은 현재 입력에 적용하지 않음 |

state와 문구 매핑은 별도 표시 계층에 둔다. `status.includes(...)` 같은 문자열 판별을 사용하지 않는다. retryPending은 전체 편집 잠금이 아니며 운동시간/휴식 틱도 저장 상태를 변경하지 않는다.

## 전이와 재시도

| 시작 | 이벤트 | 다음 상태 / 데이터 처리 |
| --- | --- | --- |
| 초기 | 읽기 시작 | loading, ready=false. 단일 Promise를 공유하여 중복 읽기 제거 |
| loading | 유효 아카이브/null 읽기 성공 | saved, ready=true. null만 정상 빈 아카이브로 해석; 쓰기 없음 |
| loading | 읽기 실패/파싱 실패 | load-error, ready=false. 디스크 원문 보존 |
| load-error | 다시 불러오기 | loading + retryPending. 하나의 읽기만 실행, 오류 맥락 표시 가능 |
| 읽기 재시도 중 | 재실패 | load-error, retryPending=false. 재시도 동작에 다시 접근 가능 |
| 편집 가능 | 입력/운동 명령 적용 | latest를 먼저 갱신하고 generation 증가, saving. unsavedAfterFailure 유지 |
| saving | 최신 generation 성공 | saved, unsavedAfterFailure=false |
| saving | 최신 generation 실패 | save-error, unsavedAfterFailure=true. 현재 메모리 아카이브 유지 |
| 임의 쓰기 상태 | 이전 generation 성공/실패 | 현재 표시 상태/최신 입력/실패 기억 변화 없음 |
| save-error | 다시 저장 | 현재 latest 전체를 새 generation으로 저장, saving + retryPending. 명령 재호출 없음 |
| 저장 재시도 중 | 새 편집 | 새로운 latest/generation을 저장 큐에 추가. 편집/입력/포커스 유지 |
| 재시도 Promise 완료 | 성공/실패 | 해당 retry 식별자의 잠금만 해제. 그 결과가 이전 generation이면 저장 상태는 바꾸지 않음 |
| saving + 실패 기억 | 일반 편집 후 최신 성공 | saved로만 실패 맥락 해제. 실패 후 새 입력만으로 성공처럼 표시하지 않음 |
| 컴포넌트 해제/다른 읽기 확정 | 늦은 읽기 완료 | 현 생명주기에 적용하지 않음. 완료된 디스크 쓰기 자체를 취소했다고 주장하지 않음 |

재시도 정책: UI 버튼과 별개로 처리 함수 입구에서 in-flight Promise/ref 잠금. 처리 중 중복 호출은 같은 Promise를 반환하거나 명시적인 no-op로 통일한다. 실패 후 finally에서 재접근을 보장한다. 자동 재시도 타이머/무한 반복 없음.

## 새 운동 정책 검토 경계

Designer implementation-split 최신 문서에서는 초안의 ‘최신 성공 전 새 운동 준비 비활성’을 철회하고 기존 허용을 유지한다. 본 초안은 그 방침을 제안하며 **PM 수용 전 새 차단 조건을 구현하지 않는다**.

완료 저장 실패 → 새 운동 준비 → 새 운동 시작에도 이전 완료 history와 미저장 안내를 유지한다. 다음 저장은 현재 운동과 history를 포함한 전체 아카이브다. 최신 성공을 확인하는 표시 조건과 새 운동을 시작할 수 있는 제품 정책을 구분한다. 영구 저장 실패가 운동 진행을 무기한 막는 경로를 만들지 않는다.
