# 화면 기록에서 서버 초안 준비

`prepareWorkoutDraft(workout, context)`는 화면의 문자열 입력을 서버 `Draft`로 변환하는 순수 함수다. HTTP 호출이나 로컬 저장을 하지 않는다. 아직 운동 화면에 자동 동기화를 연결하지 않았으며, 실제 로그인 제공자와 계정별 운동 연결은 후속 작업이다.

## 보존 규칙

- `1kg · 2회`를 복제하면 두 세트가 각각 전송된다. 카탈로그 종목은 UUID를 보내고 직접 입력 종목은 exerciseId=null과 이름을 보낸다.
- 문자열 `01.00`, `02`는 서버에 숫자 1, 2로 보내지만 `source`에는 원문과 로컬 종목·세트 ID를 보존한다. source는 원본과 독립된 복사본이다.
- 결과의 `rows[i]`는 `draft.sets[i]`에 대응하는 로컬 종목 인스턴스 ID와 세트 ID다. 서버 응답은 이 ID들을 제공하지 않으므로 응답으로 로컬 폼을 무조건 교체하면 안 된다.
- 빈칸·입력 중인 `1.`·잘못된 숫자가 하나라도 있으면 `blocked`와 해당 행의 문제만 반환한다. 부분 초안이나 0으로 변환한 빈칸을 반환하지 않는다. 부분 목록을 전송하면 서버의 이전 행을 지울 수 있으므로 전체 전송을 보류한다.
- 사용자가 마지막 세트를 명시적으로 삭제한 종목은 빈 그룹으로 source에 남는다. 모든 세트를 삭제했다면 빈 세트 배열을 전송할 수 있다. 이는 입력 중인 빈 세트와 다르다.
- 메모와 휴식 상태는 context에서 명시적으로 전달한다. 기본값으로 비워 서버 값을 지우지 않는다.
- 휴식 대상은 배열 번호 대신 로컬 종목/세트 ID로 지정하고 전송 시점의 번호로 계산한다. 대상이 삭제됐거나 미완료가 되었다면 보류하며, 호출자가 명시적으로 rest=null을 선택해야 한다.
- 휴식 종료 시각은 UTC ISO 문자열 그대로 유지한다. 준비/재시도 시 현재 시각에 휴식 시간을 다시 더하지 않는다. 서버는 1시간 한도를 최종 검사하고 이미 지난 휴식을 해제하며 마이크로초 단위로 저장한다.
- 종료 기록, 300세트 초과, 중복/빈 ID, 잘못된 종목 UUID·서버 버전·작업 ID·메모는 보류한다.

## 연결 순서

1. 기존 로컬 폼 저장을 먼저 완료한다. 서버 저장 대기 중에도 입력 원문을 보존한다.
2. 인증 토큰으로 확인된 `session.scope`와 사용자가 연결한 서버 운동 UUID를 사용한다. 로컬 workout.id를 서버 UUID로 간주하지 않는다. 다른 계정의 기록은 가져와 전송하지 않는다.
3. 최신으로 확인한 서버 version, 한 번 생성한 operationId, 보존할 note, ID 기반 rest를 전달한다. 작업 하나의 ID와 본문은 재시도 중 바꾸지 않는다.
4. blocked면 문제를 표시하고 로컬 입력을 계속 보존한다. ready면 원본 폼/행 대응을 보관한 뒤 기존 계정별 outbox에 draft를 저장한다.
5. 서버 응답은 저장 대기 전의 source에 대한 확인이다. 그 사이 더 편집한 현재 폼을 덮어쓰지 않는다. 버전 충돌은 기존 outbox의 conflict 처리로 남긴다.

운동 시작/종료 시각과 오프라인 운동의 신규 서버 가져오기는 Draft API에 포함되지 않는다. 이번 모듈은 이미 연결한 진행 중 운동의 세트/메모/휴식 변환까지만 담당한다. 작업 대기 목록에는 숫자 초안만 저장하므로 로컬 문자열과 행 대응 저장을 생략해서는 안 된다. 실제 UI 연결 전에 계정별 연결 정보 보관과 응답 확인 처리를 구현해야 한다.

## 검증

43개 프론트 자동 테스트 중 7개가 이 변환을 검증한다. 원문/ID/완료 보존, 복제·삭제 후 휴식 대상 이동, 미완료 입력 보류, 빈 그룹, 중복 ID/용량/문맥 오류, 계정별 대기 저장 복구를 포함한다.

실제 HTTP 통합 검사에서도 UI 모델의 복제·삭제 결과 → 변환 → 파일 기반 대기 저장소 → 서명 OIDC → PostgreSQL 저장·재조회를 수행한다. 전송 대기 중 입력을 빈칸으로 고쳐도 이미 준비한 초안과 현재 입력이 서로 덮어쓰이지 않는지 확인한다. 이 검사는 테스트 전용 계정/DB를 사용하며 실제 사용자 로그인이나 화면 자동 동기화의 완료를 뜻하지 않는다.
