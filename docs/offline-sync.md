# 초안 전송 대기 모듈

`src/api/outbox.ts`는 화면과 분리된 저장 대기 기능입니다. AsyncStorage처럼 `getItem`/`setItem`을 제공하는 저장소를 주입합니다. 현재 운동 화면은 기존 로컬 기록 모드이며 이 모듈의 화면 연결은 아직 하지 않았습니다.

1. 로그인 토큰으로 `createRufitSession`을 만들면 서버 `/me`에서 계정을 확인합니다. 세션은 확인 당시의 토큰을 고정해 계정 확인과 쓰기 사이에 다른 계정으로 바뀌는 것을 방지합니다. 만료되면 새 토큰으로 세션을 다시 만들고, 로그아웃할 때는 `close()`를 호출합니다. 이미 전송된 요청까지 되돌리는 기능은 아닙니다.
2. 확인된 `session.scope`를 로컬에 보관하면 오프라인에서도 같은 서버/계정의 대기 목록을 열 수 있습니다. 서버 URL과 계정 ID별로 저장 키가 분리됩니다. 토큰은 저장하지 않습니다.
3. `enqueue(workoutId, draft)`를 기다려 기기 저장 성공을 확인합니다. 입력 객체는 즉시 복사됩니다. 빈 입력값은 기존 로컬 폼 저장에 남기고, 유효한 서버 세트만 전송 대상으로 만듭니다.
4. 연결될 때 `flushOne(session)`을 호출합니다. 성공 응답을 기기에 반영한 뒤 대기 항목을 제거합니다. 응답 유실이나 제거 저장 실패 시 동일한 작업 ID로 다시 보냅니다.
5. 409 또는 서버의 현재 버전이 작업 적용 버전보다 큰 응답은 충돌로 보관하고 자동 재전송을 멈춥니다. 서버의 최신 기록과 로컬 초안을 비교해 처리해야 합니다. `discard(operationId, true)`는 호출자가 삭제 확인을 받은 뒤에만 사용합니다.

운동당 미처리 작업은 하나입니다. 이전 작업을 해결하기 전에는 새로운 초안으로 덮어쓰지 않습니다. 연속 입력은 별도의 로컬 폼에 계속 저장하고, 선행 작업 확인 뒤 반환된 서버 버전으로 최신 초안을 새 작업 ID와 함께 등록해야 합니다. 자동 버전 재설정이나 무조건적인 재전송은 하지 않습니다.

동일 저장소 객체를 쓰는 여러 인스턴스는 직렬화됩니다. 서로 다른 브라우저 탭/프로세스 사이의 동시 저장 잠금은 지원하지 않습니다. 웹에서 여러 탭으로 편집하려면 별도 탭 조정이 필요합니다. 손상된 데이터는 자동 초기화하지 않습니다.

검증은 디스크 쓰기 실패, 응답 유실, 계정 분리, 로그아웃, 토큰 변경, 버전 충돌, 손상 데이터, 입력 변경 중 스냅샷 보존을 포함합니다. `npm run test:backend`는 실제 파일 저장소와 PostgreSQL/JAR를 사용해 저장 후 응답이 끊긴 작업을 대기 목록 재생성 후 복구합니다. iOS/Android 기기에서의 앱 종료 검증과 로그인 UI 연결은 별도입니다.

`session.api`에는 같은 검증된 계정에 고정된 전체 API가 있습니다. 프로필처럼 URL에 계정 ID가 없는 수정도 로그인 화면에서 확인한 세션을 통해 호출해야 합니다. 계정 전환/로그아웃 시 이전 세션을 닫고 폼과 저장 대기 목록의 scope를 확인합니다. 닫힌 세션은 프로필·루틴 등 어떤 API도 새로 전송하지 않습니다. 토큰 갱신 시에는 새 검증 세션을 만들고 같은 계정인지 확인한 뒤 연결을 바꿉니다.
