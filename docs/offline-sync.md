# 초안 전송 대기 모듈

`src/api/outbox.ts`는 화면과 분리된 저장 대기 기능입니다. AsyncStorage처럼 `getItem`/`setItem`을 제공하는 저장소를 주입합니다. 현재 운동 화면은 기존 로컬 기록 모드이며 이 모듈의 화면 연결은 아직 하지 않았습니다.

1. 로그인 토큰으로 `createRufitSession`을 만들면 서버 `/me`에서 계정을 확인합니다. 세션은 확인 당시의 토큰을 고정해 계정 확인과 쓰기 사이에 다른 계정으로 바뀌는 것을 방지합니다. 만료되면 새 토큰으로 세션을 다시 만들고, 로그아웃할 때는 `close()`를 호출합니다. 이미 전송된 요청까지 되돌리는 기능은 아닙니다.
2. 확인된 `session.scope`를 로컬에 보관하면 오프라인에서도 같은 서버/계정의 대기 목록을 열 수 있습니다. 서버 URL과 계정 ID별로 저장 키가 분리됩니다. 토큰은 저장하지 않습니다.
3. `enqueue(workoutId, draft)`를 기다려 기기 저장 성공을 확인합니다. 입력 객체는 즉시 복사됩니다. 빈 입력값은 기존 로컬 폼 저장에 남깁니다. 화면 변환기는 하나라도 입력 중인 행이 있으면 전체 전송을 보류합니다. 유효한 행만 골라 부분 목록으로 전송하면 서버의 이전 행을 삭제할 수 있습니다.
4. 연결될 때 `flushOne(session)`을 호출합니다. 성공을 확인하면 대기 항목을 제거하고 서버 응답을 반환합니다. 호출자는 원본 폼과 연결 정보를 별도로 보관하고, 반환된 응답으로 더 최근의 입력을 덮어쓰지 않아야 합니다. 응답 유실이나 제거 저장 실패 시 동일한 작업 ID로 다시 보냅니다.
5. 409 또는 서버의 현재 버전이 작업 적용 버전보다 큰 응답은 충돌로 보관하고 자동 재전송을 멈춥니다. 서버의 최신 기록과 로컬 초안을 비교해 처리해야 합니다. `discard(operationId, true)`는 호출자가 삭제 확인을 받은 뒤에만 사용합니다.

운동당 미처리 작업은 하나입니다. 이전 작업을 해결하기 전에는 새로운 초안으로 덮어쓰지 않습니다. 연속 입력은 별도의 로컬 폼에 계속 저장하고, 선행 작업 확인 뒤 반환된 서버 버전으로 최신 초안을 새 작업 ID와 함께 등록해야 합니다. 자동 버전 재설정이나 무조건적인 재전송은 하지 않습니다.

동일 저장소 객체를 쓰는 여러 인스턴스는 직렬화됩니다. 서로 다른 브라우저 탭/프로세스 사이의 동시 저장 잠금은 지원하지 않습니다. 웹에서 여러 탭으로 편집하려면 별도 탭 조정이 필요합니다. 손상된 데이터는 자동 초기화하지 않습니다.

검증은 디스크 쓰기 실패, 응답 유실, 계정 분리, 로그아웃, 토큰 변경, 버전 충돌, 손상 데이터, 입력 변경 중 스냅샷 보존을 포함합니다. `npm run test:backend`는 실제 파일 저장소와 PostgreSQL/JAR를 사용해 저장 후 응답이 끊긴 작업을 대기 목록 재생성 후 복구합니다. iOS/Android 기기에서의 앱 종료 검증과 로그인 UI 연결은 별도입니다.

`session.api`에는 같은 검증된 계정에 고정된 전체 API가 있습니다. 프로필처럼 URL에 계정 ID가 없는 수정도 로그인 화면에서 확인한 세션을 통해 호출해야 합니다. 계정 전환/로그아웃 시 이전 세션을 닫고 폼과 저장 대기 목록의 scope를 확인합니다. 닫힌 세션은 프로필·루틴 등 어떤 API도 새로 전송하지 않습니다. 토큰 갱신 시에는 새 검증 세션을 만들고 같은 계정인지 확인한 뒤 연결을 바꿉니다.

삭제·입력 거절로 더 이상 같은 요청을 처리할 수 없는 확정 응답(400/404/410)도 초안을 지우지 않고 `conflict`로 남깁니다. `reason`으로 `REQUEST_REJECTED`, `RESOURCE_UNAVAILABLE`, `STATE_CONFLICT`, `REMOTE_CHANGED`를 구분합니다. 이전 저장 형식에는 reason이 없을 수 있습니다. 이 항목의 자동 전송을 중지해 다음 운동의 정상 대기 요청이 막히지 않게 합니다. 원본이 삭제됐다는 이유로 자동 재생성하지 않습니다.

401/403 인증·권한 문제, 408/429/5xx 일시 실패, JSON으로 읽지 못한 응답은 기존 `pending`을 유지하고 오류를 반환합니다. 저장 성공 여부가 불명확한 요청을 확정 실패로 처리하지 않습니다. 실제 서버에서 초안을 대기시킨 뒤 해당 테스트 운동을 취소·삭제하고, 초안 보존과 다음 운동 저장이 함께 되는 것을 검사합니다.

실제 서버 연결 스크립트는 루프백 주소의 `rufit_test` DB·계정만 허용합니다. 다른 DB, 원격 주소, URL 옵션은 JVM 시작 전에 거절하며 자식 서버에 다른 작업의 Spring/JVM 설정을 넘기지 않습니다. 이 검사는 앱 런타임이 아닌 통합 검증 스크립트에만 적용합니다.

서버 응답에 유효한 UUID 형식의 `X-Request-Id`가 있으면 `ApiError.requestId`로 보존합니다. 오류 신고·검증 시 서버 로그와 대조하는 번호입니다. 번호가 없거나 임의 문자열이면 null이며, 토큰이나 저장 작업 ID로 대체하지 않습니다. JSON을 해석하지 못한 오류 응답도 헤더의 유효한 번호는 유지합니다.

화면 입력에서 서버 초안을 만드는 준비 함수는 [변환과 보존 규칙](workout-draft-mapping.md)에 정리했습니다. 이 함수는 계정 연결이나 HTTP 호출을 수행하지 않습니다.

계정별 원본 폼과 전송 요청을 함께 복구할 때는 [연결 컨트롤러](connected-workouts.md)를 사용합니다. 선택적인 beforeRemove 훅은 폼 확인을 영구 저장한 뒤 대기 요청을 지우도록 합니다.

## 완료 기록 수동 이전과 측정 동기화 (2026-11-02)

네이티브 앱에서 실제 서버 계정 확인이 끝나면 **설정 → 계정 기록 동기화**를 사용할 수 있습니다. 웹의 기기 기록 모드에는 이 메뉴가 노출되지 않습니다. 위의 진행 중 초안 자동 전송과 별개로, 이번 화면은 완료한 운동과 날짜별 체중·삼대 측정값을 수동 전송합니다.

- `src/features/sync/WorkoutTransferPanel.tsx`: 완료한 기기 운동을 현재 계정에 연결하는 확인 절차와 업로드 진행 상태를 표시합니다. 사진·진행 중인 운동은 제외하고 기기 원본을 유지합니다.
- `workoutTransfer.ts`: 네트워크 요청 전에 UUID와 원문을 장부에 저장합니다. 응답 유실 후 같은 키로 재시도하고 확인된 기록은 다시 보내지 않습니다. 이미 전송한 원본이 바뀌면 자동 덮어쓰기를 중단합니다. 수동 입력한 과거 날짜와 시간 미측정 상태를 보존합니다.
- `MeasurementTransferPanel.tsx`, `measurementTransfer.ts`: 기기/서버의 날짜별 측정값을 비교하고 사용자가 전송 방향을 선택합니다. 서버 버전 충돌이나 비교 이후 기기 값 변경은 저장을 중단합니다. 가져오기는 선택한 날짜만 변경하고 다른 날짜는 유지합니다.
- `transferStorage.ts`: 같은 앱 인스턴스의 전송을 직렬화하고 기기 기록을 최초 전송 계정에 연결합니다. 다른 계정으로 같은 기기 자료를 재전송하지 않습니다. 계정 연결 해제/자료 분리 UI는 아직 없으므로 최초 연결 계정을 확인해야 합니다. 토큰을 전송 장부에 저장하지 않습니다.

백엔드는 V27 마이그레이션과 `/api/v1/measurements/{kind}` API가 포함된 버전이 필요합니다. 기존 실행 중인 서버를 자동 재시작하거나 실제 사용자 기록을 전송하지 않았습니다. 사진은 미디어 저장 API가 없어 이번 동기화 대상이 아닙니다.

검증: 프론트 전체 검사 214개 테스트, 타입·린트(기존 경고 2개), 스타일 일치 검사와 Web/iOS/Android export 통과. 신규 테스트는 전송 응답 유실, 디스크 저장 실패, 다른 계정 차단, 원본 변경, 과거 날짜 보존, 측정값 버전 충돌, 다운로드 시 다른 날짜 보존, 로그아웃, 실제 컴포넌트 선택 동작을 포함합니다. 백엔드는 별도 PostgreSQL에서 전체 205개 테스트가 통과했습니다. 실제 OAuth 로그인·휴대전화에서의 왕복 전송은 미검증이며 빌드 성공과 구분합니다.
